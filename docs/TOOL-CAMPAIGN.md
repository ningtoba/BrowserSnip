# TOOL CAMPAIGN — one tool per agent

The queue for auditing every tool against the live build. One row per tool, one
agent per tool, no agent touches a file it does not own.

**The rule.** A tool is verified only by measuring **what the user sees, and what
the file contains.** Both halves or neither:

- **browser evidence** — a real Chromium tab against a live dev server (started
  *detached*: `(nohup npx vite --port 52xx --strictPort >/tmp/xx.log 2>&1 &)`),
  a screenshot of the tool holding real content, and ink measured **off the
  canvas bitmap** — never inferred from a node count or a reported total.
- **a byte-level check of the exported file** — open the download with PyMuPDF
  and measure what the file itself draws (`get_pixmap` ink vs. the untouched
  source), not merely that an object exists in it.

A green unit run is neither half. Every assertion written around this area so far
has been about **counts and presence** — blocks extracted, marks added, objects
written — and never about output. That is the same shape as the markup bowtie,
the vacuous image compression and the zero-ink link: `edit-pdf` once shipped a
`area=0` mark with 1,400 passing tests. The symptom was real; the tests were
blind.

**Status** — `unexamined` → `defect-found` → `fixed+deployed` → `verified-good`.
A row may only reach `verified-good` with both evidence halves recorded.
`blocker:` in the last column means the true cause sits in a shared module the
tool's owner must not edit without a decision; the fix is sequenced, not
improvised.

1. **A test double that omits a contract cannot catch a bug in it.** The
   `renderPage` double in `edge-organize.test.ts` returned no `finished` property
   at all, so a helper that never awaited the paint looked fine and 1,875 tests
   stayed green over a CBZ of blank pages. A double has to model the *ordering* —
   nothing inked until `finished` resolves, inked after — not just the shape, and
   `finished: Promise.resolve()` is the same blind spot with better manners.
   Where it still stands: `convert-to-bytes.test.ts:99`, `edge-convert-to.test.ts:81`,
   `edge-edit.test.ts:104`, `edit-bytes.test.ts:117` and `ux-text.test.ts:97`
   return no `finished`; `pages-out.test.ts:77` returns one already resolved;
   `optimize-bytes.test.ts:136` returns none and paints **synchronously**, so its
   `rasterize-pdf` structural checks are safe today but could never see a paint
   race. Repaired with the `rasterize-pdf` row (`4ba14b6`): its own double
   (`tests/pdf/rasterize-ink.test.ts`) lands the ink in a later task and counts
   every read of a page canvas that happens before it.
   `edge-optimize.test.ts` was repaired with the `deskew-pdf` row (`8313e2d`): its
   double now hands out background-fill pixels until `finished` resolves and inked
   ones after, in a later task — a `finished: Promise.resolve()` lands the paint in
   a microtask the awaiting caller cannot lose to, which is how a double can be
   generous and still blind. Each belongs to its own tool's row, where the
   bytes can say whether it matters. The mirror-image mistake is just as live:
   the same `edge-organize.test.ts` double answered every `Do` with a
   `paintXObject` operator that real pdf.js emits only for a *form* XObject, so
   an image page scored as painted in jsdom and blank in the browser — a double
   can hide a bug by being **more generous** than the API, not only by omitting
   it. Repaired with that row (`a216d03`): the double now reads the page's
   `/Resources`, answers an image with `paintImageXObject`, and **throws** on a
   `Do` it cannot resolve rather than guessing an id, so generosity cannot
   silently come back. Model a double from a captured real response (an operator
   list, a text content item) when the rule reads those ids, and make the wrong
   vocabulary cost a test rather than pass one.
2. **Blank output is silent.** No console error, no exception, a plausible file
   size, and a report line true about everything except the pixels — six
   identical 23 690-byte JPEGs passed an “is this a PNG” check. So an ink
   assertion belongs in every rasterising tool's test: compare the archived
   bytes (`organize-campaign-bytes.py`, `cbz-bytes.mjs` measure non-white
   coverage out of the real download), never the byte count.
3. **A helper is a defect only where a tool reaches it.** `rasterizePages` had
   one caller and it was a shipped tool, which is what made this user-facing.
   Re-audited for `deskew-pdf` (`grep -rn "\b<name>\b" src/`, per helper):
   `isBlankPage`, `rasterizeWithOptions` and `scannerEffect` still have **no
   caller anywhere in `src/`** — dead with a known flaw, left alone — while
   `detectSkew`'s canvas read is awaited now (`8313e2d`), `applyColorFilter` is
   reached by `pdf-to-greyscale`'s **raster method — a choice the user makes, not a
   fallback reached after the operator path**, corrected by the caller audit below,
   and `deskewAngleFor` — dead, correct, and tested —
   is the bridge the `deskew-pdf` call site should have used from the start.
   A broken helper nobody reaches is a maintenance note, not a defect; a
   *correct* helper nobody reaches is the same note with a bug waiting in the
   caller that ignored it.
4. **Prove two tools against each other.** The `ocr-pdf` cache collision — one
   page answered with another page's words, a fabricated result rather than a
   weak one — was found only because the row was asked for an end-to-end proof:
   plant text, rasterise it with `rasterize-pdf`, make `ocr-pdf` return it. Every
   per-tool test in this repo recognised **one** page, so a bug whose signature
   is "the second page reads like the first" is invisible to them *by
   construction*: each test's fixture never contains the pair the defect needs.
   A cross-tool chain has a second virtue — it fails loudly if **either** link
   regresses, which is why `ocr-check.py` scores the planted strings rather than
   checking the output is non-empty. Where a tool's input is another tool's
   output, test the pair.

5. **An option that is accepted, plumbed and never observable is not a dead
   parameter, it is a silent one.** `RenderOptions.filter` had a type, a docstring, a
   call site in four places and an assignment to `ctx.filter` — and had never done what
   it says, because pdf.js's `beginDrawing` calls `resetCtxToDefault`, which writes
   `filter = 'none'` over the caller's value before its first operator
   (pdfjs-dist 4.10.38, `build/pdf.mjs:7610-7617`). Grepping for *readers* of an option
   finds this class never; the only test is a measurement that changes when the option
   changes. `docs/research/colour-measure.sh` is that measurement for `filter`, per
   region, for all four consumers. The same question, asked of the rest of
   `RenderOptions` and of the pdf.js render call it forwards to — **none of these has a
   measurement proving it does anything**, listed rather than fixed, because a claim
   about them belongs to a row with bytes behind it:
   · `background` — assigned to `ctx.fillStyle` and filled, then overwritten by
     pdf.js's own `background || '#ffffff'` fill in `beginDrawing` (`:7686-7687`), which
     this module never passes a value to. Every caller in `src/` asks for `'#ffffff'` or
     `undefined`, so nothing can show the difference today; a coloured paper request
     would be silently dropped.
   · `rotation` — read, and forwarded to `page.getViewport({rotation})`, but **no caller
     in `src/` passes it** (`grep -rn "renderPage(" -A 4 src/ | grep rotation:` → the one
     hit is this module's own default), so the "render at an angle other than /Rotate"
     path has never been driven.
   · `RenderOptions.scale` — declared on the interface and never read: `renderPage` takes
     scale as its second argument, and every caller passes it there. The field is a trap
     for the next caller that sets it.
   · the pdf.js task options this module does *not* forward — `intent`,
     `annotationMode`, `pageColors`, `transform`, `printAnnotationStorage`. Fine as
     choices, but `annotationMode` and `pageColors` are the two that would change what a
     page looks like, and nothing here says which one the app wants by decision rather
     than by omission.
   The mirror of standing rule 3: a *correct* thing nobody reaches waits for a caller; a
   *broken* thing everybody believes in has already shipped four tools.
